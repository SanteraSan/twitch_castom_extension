1. Ubuntu для разработки, Windows для эфира
Страница оверлея — обычный сайт из HTML, CSS и JavaScript. На Ubuntu ты открываешь её в браузере и в OBS. На Windows в эфире OBS открывает ту же страницу. Игру для этого видеть не обязательно.

Lutris с релизов GitHub — нормальный способ поставить программу на Ubuntu. Сама Heroes of the Storm через него часто ломается: лаунчер Battle.net капризничает к версии Wine, а установка «в один клик» с сайта Lutris нередко заканчивается тем, что лаунчер открылся, а игра внутри него не поставлена. Имеет смысл ставить Battle.net, и уже из него игру. Если не заведётся, проект из-за этого не останавливается. Для рамок достаточно одного скриншота твоего интерфейса с Windows: миникарта и панель героя на том разрешении, в котором ты стримишь.

OBS из Flathub для проверки картинки подходит. Источник «Браузер» грузит адрес http://127.0.0.1, а не файл с диска. Страницу раздаёт маленькая локальная программа, OBS только показывает её. Захват игры на Ubuntu и на Windows устроен по-разному, и это не мешает: оверлей — отдельный слой поверх захвата.

2. API Twitch
Для рамок и для вспышек по экрану игры Twitch не нужен. Ставить его сейчас значит смешать вторую фазу с первой.

Когда дойдём до событий канала, ставятся две вещи, не Developer Rig.

Приложение на dev.twitch.tv/console/apps. Оно выдаёт client id и секрет. Секрет живёт только в локальной программе на твоём компьютере. В страницу OBS его класть нельзя: страница уходит в кадр, секрет вместе с ней.
Twitch CLI. На Linux его ставят через Homebrew командой brew install twitchdev/twitch/twitch-cli. У него есть учебный сервер событий: подписка, фоллов и рейд можно вызвать с компьютера, без эфира. Настоящий адрес событий Twitch — WebSocket EventSub. Публичный сервер и вебхук для этого не нужны.
Developer Rig — отдельная программа для расширения, которое зритель видит в плеере. Она появится во второй фазе, вместе с кнопками. В первую фазу не входит.

Правило в чате — поручение модели. Оно не замок. Замок — это тест и форматтер: команда либо проходит, либо нет, и от вежливости модели это не зависит. Ревьюер смотрит дифф и цитирует правило. Если правила на случай нет, он пишет «в правилах нет решения» и спрашивает тебя, а не выдумывает стиль. Фразу «всегда подчиняйся правилам» в файл добавлять бессмысленно. В правило попадает конкретный запрет и команда проверки.

TDD здесь про поведение, которое можно утверждать текстом. Пример: пришло сообщение «сыграй объектив» один раз, повтор за ту же секунду игнорируется, неизвестное имя не роняет страницу. Рисунок рамки тест не оценивает. Его смотрим в браузере. Так и закладываем в скилл, иначе агент будет рисовать тесты на цвет пикселя и считать это проверкой.

Писать эти файлы лучше отдельным заходом, до первой фичи, и сразу с одним падающим тестом на команду «сыграй анимацию». Иначе правила появятся после того, как код уже разъехался.

Логику оверлея стоит держать в маленьком проекте на Node.js с тестами, а OBS по-прежнему открывает собранную страницу. Чистый HTML без тестового запуска сделает TDD заявлением в чате.

7–8. Анимация готовых картинок
Бесплатные программы есть, Illustrator для этого не нужен. Illustrator рисует векторы. Анимация у Adobe живёт в After Effects, и он платный.

Для этого оверлея рабочая связка другая.

Картинки готовишь как есть, PNG или SVG. Если понадобится обрезать и разложить вектор, на Ubuntu хватает бесплатного Inkscape.
Движение, которое является частью интерфейса (вспышка рамки, появление, прозрачность), пишется в CSS страницы. Отдельный редактор не участвует, и в OBS это уже играет.
Более сложный ролик по готовым слоям собираешь в Glaxnimate. Он бесплатный, стоит и на Linux, и на Windows, открывает твои картинки и сохраняет Lottie, SVG, WebP или GIF. Lottie страница в OBS умеет проиграть. Synfig тоже бесплатный, но для коротких вспышек он тяжелее, чем нужно.
Glaxnimate ставим в тот день, когда ты принесёшь первые картинки. Сегодня он ничего не ускорит.
